# Submission repository checks

Reviewed 15 November 2026. The selected algorithm, fitted weights, official scorer
and frozen source/report/configuration checks are unchanged from the verified V2
release. This repository contains code, pinned dependencies, external benchmark
evidence, the local interface and one attributed external-only fitted artifact.
Competition assets, target CSVs, private viewer data, credentials, logs, environments,
old releases, meeting media and internal planning are excluded.

## Evidence

- The original 92-file source edition passed its inventory and all frozen hashes.
- Independent review passed 37 security/reproduction tests and 30 subtests and
  successfully inferred a synthetic 80-frame sequence with the included model.
- Gitleaks v8.30.1, acquired from its official release with the published archive
  checksum verified, found no secrets in the submission source. No custom finding
  suppression or baseline was used.
- pip-audit 2.10.1 and the OSV batch API each checked all 31 exact versions in
  `requirements.lock`; neither reported a known dependency advisory at review time.
- The prior complete source-copy suite passed 170 tests and 34 subtests, and its
  actual target output regenerated byte for byte. Repository-specific inventory
  tests additionally cover Git metadata, ignored local outputs, extra staged files,
  source tampering and duplicate manifest entries.

These checks have bounded scope. They do not establish target accuracy or certify
the absence of every possible vulnerability. Tool reports and private execution
logs remain outside this repository.

## Static-analysis findings and their disposition

Bandit 1.9.4 reported four medium and twenty-one low-severity findings; no high-
severity findings. Findings were reviewed rather than disabled globally:

| Finding | Reviewed boundary |
|---|---|
| Two B314 XML parsing warnings | The frozen parsers consume operator-supplied organizer metadata or checksum-verified licensed external metadata. They are not upload endpoints or parsers exposed to web requests. Arbitrary untrusted XML is outside the supported input contract; do not use it. The generic XML warning remains a documented limitation. |
| Two B310 URL-opening warnings | The acquisition helper uses a fixed HTTPS Figshare article endpoint and checks download URL prefixes before requesting them; it verifies published sizes/MD5 afterward. It does not accept an arbitrary caller-supplied URL through its CLI. |
| Subprocess/import and partial executable-path notices | The fixed local runners/builders call known Python/Git tools with argument arrays, without shell interpolation. Executable resolution assumes a trusted local environment/PATH. |
| XML import notices | Same local trusted-input boundary as the parser warnings above. |

The fitted model is checksum checked before joblib loading. It is not safe to load
arbitrary pickle/joblib files; the repository accepts only the named trusted
artifact. Model/source hash checks are integrity checks, not digital signatures.

## Before organizer submission

1. Verify the tracked manifest with `python -B scripts/verify_repository.py`.
2. Run the synthetic suite and exact target reproduction in the pinned environment.
3. Confirm the team-selected method and technical note describe the actual CSV.
4. Make the reviewed repository public, as required by the organizer.
5. Supply that public URL and upload the team CSV/short document through the
   organizer's form. Keep restricted files out of Git even while the repo is private.
