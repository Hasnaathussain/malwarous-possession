# V2 external data and CPU video resource review

Reviewed 2026-11-14. Scope: a bounded follow-up to `planning/RULES_AND_SOURCES.md`, for the November 17 submission deadline and the available Xeon E5 / 16 GB RAM / no CUDA machine. This review inspected public documentation, licences and manifests only. It did not read target-match assets, download dataset/model payloads, contact anyone, accept access conditions, inspect GTT implementation/outputs, or reopen the frozen v1 candidate.

## Decision

**No newly independent, accessible dataset with adequately documented dense team-possession and live/dead truth was established.** Do not call event timestamps, reconstructed ball tracks, detector outputs, or a provider's calculated nearest-player possession independent H/A/D ground truth. The seven Sportec matches remain useful development material; all have now been consumed, so none can become a newly blind test by renaming a split.

For the separately registered v2 study, use the existing six development matches with whole-match grouped validation and report that limitation. Keep the previously consumed seventh match out of model selection. An external video viewer can still be useful, but its operation cannot establish possession accuracy. Root decision after this review: **do not download gated SoccerTrack or a detector now**. Spend the CPU budget on the learned temporal study; detector benefit to control semantics is unproven.

## SoccerTrack viewer: concrete manifest, access and alignment

[HF dataset card](https://huggingface.co/datasets/atomscott/soccertrack-v2/blob/325bd4c57ee8e135ab652f3921d274526ada496b/README.md) identifies v1.2 as synchronized to decoded half-video frames, with unique IDs across halves. Its coordinates use a 105 × 68 m pitch, centred origin, x camera-right and y toward the nearer touchline. Team side is not automatically home/away. The gate is visible on the [file listing](https://huggingface.co/datasets/atomscott/soccertrack-v2/tree/main); access must already be valid or its concrete conditions must be reviewed by the user. No acceptance, access request or bypass was attempted.

LFS content hashes are redacted by the gate; do not mistake Git blob object IDs for payload SHA-256 hashes.

**Proposed bundle, not downloaded:** once valid access and clip alignment are established, pin the dataset SHA and select only `mot/clips/118577.mp4`, `mot/118577.txt`, plus `mot/README.md`. The [card](https://huggingface.co/datasets/atomscott/soccertrack-v2/blob/325bd4c57ee8e135ab652f3921d274526ada496b/README.md) describes paired four-minute clips. The MOT README itself returned HTTP 401 during this review, so its clip offset/frame-base convention remains unverified. Do not silently pair the short clip with full-half GSR or assume offset zero. A box-overlay viewer is feasible once the pairing contract is readable; a verified pitch-coordinate viewer additionally needs the correct clip-to-half offset and calibration/GSR slice.

The [GSR format document](https://github.com/AtomScott/SoccerTrack-v2/blob/a752d294df2a0e816e827b70f284980698f5a50e/docs/format-gsr.md) explicitly warns its old flat-record schema differs from shipped COCO-style objects: attributes are nested, frame IDs encode sequence/frame, and pitch positions use `bbox_pitch` bottom-middle fields. It also warns declared image dimensions are wrong for nine matches. Validate actual versioned files and decoded dimensions rather than implementing the illustrative schema blindly. The [BAS format](https://github.com/AtomScott/SoccerTrack-v2/blob/a752d294df2a0e816e827b70f284980698f5a50e/docs/format-bas.md) defines action instants such as Out, Throw In and Free Kick, not exhaustive live/dead intervals; event-gap filling would manufacture labels.

The authors' [public Drive folder](https://drive.google.com/drive/folders/1N2Qx2qkFgRtpbHitl2Vh6sLVYGgqkWwn) is linked from their landing page, but its contents, sizes and revision equivalence were not established here. It is not an assumed substitute for accepting unseen HF conditions.

## Ungated video sync fallback

Use locally generated motion with known frame indices, changing team-coloured markers and a synthetic ball for the immediate viewer integration test. Put synthetic provenance visibly in the viewer. A known synthetic change at frame k can test offsets and seeking precisely; it supplies no real-football accuracy claim. This requires no third-party footage download.

If an encoded third-party movie is needed later, Blender Foundation's [official Big Buck Bunny project licence](https://peach.blender.org/about/) grants CC BY 3.0 to the published movie/project results, excluding logos/trademarks and identifying separately credited textures. Its [official download index](https://download.blender.org/peach/bigbuckbunny_movies/) lists `BigBuckBunny_320x180.mp4.zip`, 64,657,225 bytes (index timestamp 2026-07-22). It is an ungated, nonfootball playback-only alternative; preserve Blender Foundation attribution and link the licence, and state changes such as clipping/downsampling. Neither it nor its metadata provides tracking or football labels. Only the HTML licence and index were read; the archive was not downloaded, its contents/checksum were not verified, and it is not needed for the chosen synthetic path.

## Bounded validation recommendation

1. Follow `V2_STUDY.md` as the experiment authority; use whole matches as groups, retain dead frames and missingness, and freeze the candidate set before results. Do not create random frame splits.
2. Report official spellF1 plus macroF1 per held-out development match and pooled summary. Explicitly call this reused-source development validation, with uncertainty from few matches and provider/domain differences. A stronger development result does not predict hidden target performance.
3. Treat an external viewer test as alignment/rendering evidence only: seeking, frame stepping, IDs, image boxes and time alignment. Any possession overlay is a model prediction and must be labelled as such. No manual annotation or correction of the competition match.
4. A video feature needs independent dense labels to justify accuracy-driven selection. Without them, restrict it to a preregistered diagnostic/ablation with honest limits; do not tune it through target inspection, public five-minute labels or event-derived pseudo-truth.
5. Stop this source scan here. The next useful action is a small validated experiment using already permitted data, or resolving an actual access/licence issue through an explicitly authorized channel. No new contact or gate acceptance follows from this review.

No new dataset/model payload was downloaded as part of this review. Exact runtime, downloaded-file checksums, model package compatibility and the short-clip alignment contract therefore remain unmeasured.
